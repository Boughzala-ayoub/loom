## Should fix

1. **P2. Create PR can push one branch and return a comparison URL for another.**

Locations: `src/main.ts:6932`, `src/main.ts:6938`, `src/main.ts:6939`.
Connected callers: desktop `src/main.ts:6923`, CLI/phone `src/main.ts:9062`, phone `src/remote/changes.ts:277`.

`prUrl` refreshes the shared `th.branch`, awaits more Git operations, pushes mutable `HEAD`, and finally reads the shared branch cache again for the URL. Another request or an agent can switch the checkout across these awaits. Neither the pushed source nor the URL's head is captured for this operation. The CLI event handler runs requests independently at `src/main.ts:9855`; there is no per-thread Git serialization preventing this schedule.

Reproduced two schedules with a fresh clone, distinct local `topic-A` and `topic-B` commits, and a real temporary origin that initially had neither branch:

- **Switch after the push.** Start Create PR on A. Its real `git push -u origin HEAD` succeeds and creates remote A. Hold delivery of that successful reply, run the actual CLI `git ... switch topic-B` handler, then release the reply. Both the actual CLI PR handler and desktop `createPR` return/open `https://github.com/review-fixture/loom/compare/main...topic-B?expand=1`. Remote B does not exist. The cache now says B, although this PR operation pushed A.
- **Switch before the push.** Start on A and hold delivery of the remote-default ref read. Switch to B with real Git, as an agent could, without refreshing Loom's cache. Release the read. The real push creates remote B, but `prUrl` returns `main...topic-A?expand=1`. Remote A does not exist.

These used the current extracted production functions. Ref reads, switches, commits and pushes were real Git. A controllable promise delayed a Git reply at the asynchronous boundary; it did not fabricate a successful push. Only the displayed origin URL was GitHub-shaped, and rendering/status boundaries were inert. No live GitHub repository was contacted.

Fix: capture the exact attached branch for the whole operation. Push that full local ref explicitly as `refs/heads/<branch>:refs/heads/<branch>` and encode the same captured name in the URL. Preserve refusal for an unavailable, detached or unborn source. Do not reread `th.branch` after the push. Add both interleavings as regressions in the shared PR helper so desktop, CLI and phone stay aligned. In a real-Git control, pushing `refs/heads/topic-A:refs/heads/topic-A` while HEAD remained on B correctly published A and set A's upstream.

If skipped, a successful Create PR can publish an unintended branch or open a comparison for missing or different code. This is a newly reported adjacent finding; both specific round-7 defects below remain closed.

Evidence: `pr-concurrency.mjs`, `pr-before-push.mjs` and their records in `results.json` under the temporary evidence directory below.
