# Third review of branch deletion

What this change does: `eae0e61` keeps a branch when a worktree has `index.lock` or `HEAD.lock`. `cd4e545` drains Git's stderr concurrently and retains its last 64 KiB. This review covers `f5c7461..cd4e545`, including the preserved prior report in `d5ffaea`, and assumes ordinary Git commands may run in other worktrees while Loom closes a thread.

The noisy reference-transaction hook finding is closed. The original delayed-smudge-filter checkout case is also fixed, but the checkout race remains in a later phase.

## Must fix

1. **P1. A checkout between its index write and HEAD update can still lose its branch.** `src-tauri/src/deletion.rs:116-119`, `src-tauri/src/deletion.rs:182-189`.
   - **What this is:** The native helper reads worktree HEAD files and samples two lock files before deleting the approved branch tip. It repeats that scan after deletion and restores the branch if the scan finds it in use.
   - **Problem:** A normal `git switch topic` releases `index.lock` before taking `HEAD.lock`. A `post-index-change` hook can pause it there with HEAD still detached and both locks absent, so both scans miss the checkout and deletion reports success.
   - **Fix:** Coordinate deletion with checkout using locks Git honors for worktree HEAD updates across the check and deletion. If that coordination cannot be established, keep the branch; preserve the expected-tip comparison and add the reproducer below as a native regression test.
   - **If we skip it:** The checkout exits successfully with HEAD naming a deleted branch. `git rev-parse --verify HEAD` fails, and Loom has already reported the branch deleted and may remove its local Git settings.

### Reproduction

The driver contains the actual current production functions, regenerated by `.cache/create-re-review-delete-driver.mjs` and compiled with `rustc --edition 2021`. Only the common-directory lookup uses a small real-Git wrapper. Production code was not edited.

Run `node .cache/re-review-post-index-checkout.mjs`. It creates a disposable repository and a detached linked worktree, then pauses `git switch topic` in a local `post-index-change` hook. Git documents this hook as running when the index is written: [Git hook documentation](https://git-scm.com/docs/githooks#_post_index_change).

Verified against `cd4e54512cb699fc382d78d6e1a8565bee0001a3` with Git `2.39.1.windows.1`:

```text

native deletion: deleted
checkout exit: 0
HEAD: refs/heads/topic
rev-parse --verify HEAD: fatal: Needed a single revision
```

Evidence: `.cache/re-review-post-index-checkout-jOnHC5/evidence.json`. The hook was released and the checkout process finished in the script's cleanup. No watcher was started.
